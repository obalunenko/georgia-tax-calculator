# Bug Report: Unknown command exits with status 0

**Type**: Spec gap (no requirement for the exit status of an unknown command)
**Severity**: Low (interactive tool; affects scripts and CI that call the CLI)
**Feature**: 005-cli-platform
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15
**Fixed**: 2026-11-15 (005 T012)

## Description

`ge-tax-calc foo` prints

```text
Command [foo] not supported.
Try --help flag to see how to use it
Exit...
```

and exits with status 0 (checked on 2026-11-15 with a local build of
`0bafe32`), so a script cannot tell a typo from a successful run.

Cause in the code: urfave/cli v3 (`vendor/github.com/urfave/cli/v3/help.go`,
`helpCommandAction`) returns `Exit("No help topic for '<name>'", 3)` when
`CommandNotFound` is nil, but calls `cmd.CommandNotFound` and returns `nil`
when it is set. `main.go` sets `app.CommandNotFound = notFound`
(`cmd/ge-tax-calc/handlers.go`), and `CommandNotFoundFunc` has no error
result, so the custom message replaces the non-zero exit.

## Artifact Traceability

### spec.md

- **Affected user story**: US1 (start the CLI and choose a command),
  acceptance scenario US1.3, which records "exits with status 0".
- **Affected requirements**: FR-004 (unknown command message) says nothing
  about the exit status; FR-005 covers only command errors.
- **Gap identified**: no requirement that an unknown command end with a
  non-zero status.

### plan.md

- **Affected sections**: Technical Decision 1 (urfave/cli v3 root command
  with hooks).
- **Impact**: record how the custom message and a non-zero status are
  combined.

### tasks.md

- **Affected tasks**: T005 (`printHeader`, `notFound`, `onExit`).
- **False completions**: none; T005 matches the migrated spec.
- **Missing tasks**: make an unknown command exit non-zero and test it.

## Root Cause Analysis

The custom handler was added for a friendlier message; the side effect on the
exit status of urfave/cli's `CommandNotFound` contract was not noticed and
was never specified.

## Recommended Fix

1. Run `/speckit-bugfix-patch` to update spec, plan, and tasks.
2. Run `/speckit-bugfix-verify` to confirm consistency.
3. Implement one of: drop `CommandNotFound` and rely on urfave/cli's exit 3
   (message "No help topic for 'foo'", optionally with `Suggest`); or keep
   the custom message and return a `cli.Exit` error from the root command
   when an unknown command was seen. Add a test that runs the root command
   with an unknown argument and checks the exit code through
   `cli.OsExiter`.
