# Bug Report: `--version` marks clean builds as modified

**Type**: Dependency issue
**Severity**: Medium (every build, including release binaries, reports
`+CHANGES`, so version output in bug reports cannot be trusted)
**Feature**: 005-cli-platform
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

`github.com/obalunenko/version` v1.3.1
(`vendor/github.com/obalunenko/version/version.go`, `init`) reads build info
and sets `modified = true` when it sees the `vcs.modified` key, without
checking its value:

```go
case "vcs.modified":
	modified = true
```

Go writes `vcs.modified=false` for builds from a clean tree, so the suffix is
added to every VCS build. Checked on 2026-11-15: a build from a clean
worktree of `0bafe32` has `vcs.modified=false` in `go version -m`, and
`ge-tax-calc --version` prints

```text
| short_commit: 0bafe32+CHANGES |
| commit:       0bafe32f28e1b8223f7d99f7846d4c9498b00a98+CHANGES |
```

Release binaries are built by goreleaser from a clean tagged checkout, so
they are affected too (not checked against a published release).

## Root Cause Analysis

The library treats the presence of `vcs.modified` as "modified"; Go always
writes the key for VCS builds, with `true` or `false`.

## Recommended Fix

1. Run `/speckit-bugfix-patch` to update spec, plan, and tasks.
2. Run `/speckit-bugfix-verify` to confirm consistency.
3. In `github.com/obalunenko/version`: set `modified = setting.Value ==
   "true"`, add a test, release a new version.
4. Here: bump the dependency in `go.mod`, run `make sync-vendor`, and check
   `--version` on a build from a clean worktree.
