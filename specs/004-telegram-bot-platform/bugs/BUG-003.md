# Bug Report: Known chats are lost in Docker, and store errors are silent

**Type**: Spec gap (no persistence or runtime-user requirement for the
Docker deployment) and untested flow
**Severity**: Medium (SC-002 fails for the documented Docker deployment)
**Feature**: 004-telegram-bot-platform
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15
**Fixed**: 2026-11-15 (004 T023–T026)

## Description

1. **No persistent storage.** The runtime image
   (`build/docker/bot/Dockerfile`) sets no `WORKDIR`, and
   `deployments/docker-compose/bot-docker-compose.yml` mounts no volume. With
   the default `USER_STORE_PATH=users.json`, the store is written to
   `/users.json` inside the container. `make bot-up` runs `up --build`, which
   recreates the container when the image changes, so the file and all known
   chats are lost; SC-002 ("after a restart … every previously seen chat
   receives the welcome-back message") does not hold.
2. **Silent store errors.** `userStore.load` returns on any read or JSON
   error and `userStore.save` ignores write errors (`cmd/bot/users.go`).
   A corrupt file or a read-only path stops chat tracking without a log line.
3. **Runs as root.** The image has no `USER`. Adding one without a writable
   directory would make every write fail, and because of item 2 nobody would
   notice (004 tasks.md gap 8).

- **Missing tasks**: data directory, non-root user, and volume; logging of
  load and save errors; tests for the store.

## Root Cause Analysis

The store was designed for running the binary directly, where the working
directory persists. The Docker deployment was added later without a volume,
and ignoring errors hid the problem.

## Recommended Fix

1. Run `/speckit-bugfix-patch` to update spec, plan, and tasks.
2. Run `/speckit-bugfix-verify` to confirm consistency.
3. Implement: in the runtime image create `/data` owned by a non-root user,
   set `WORKDIR /data` and `USER`; mount a named volume at `/data` in
   compose; log store load errors (except a missing file) and save errors;
   add table-driven tests for the store with `t.TempDir()`.
